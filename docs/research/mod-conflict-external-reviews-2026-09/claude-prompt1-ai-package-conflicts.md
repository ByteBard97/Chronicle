# Whiterun NPC AIPackages Conflicts: What Chronicle Will Collide With, and How

## TL;DR
- **Your direct `AIPackages` override on these 19 base records is a textbook "last plugin in load order wins" record-level clash — and the single biggest collision is AI Overhaul SSE (36,103 endorsements), which edits the exact same NPCs' package lists in the exact same way you do.** Whichever of the two loads last silently wins; the loser's Flee packages (or AIO's schedules) vanish with no error.
- **Immersive Citizens is a different beast: it injects packages via quest reference-aliases, not base-record edits, so it will NOT record-clash with you — but it WILL fight you at runtime, and that conflict is invisible to xEdit and unfixable by a merge patch.** Populated Cities Towns Villages and JK's Whiterun do NOT edit these NPCs' package lists at all (PCTV adds 189 brand-new NPCs, 28 in Whiterun; JK's edits cells/navmesh/idle markers), so neither produces a base-record package conflict; Cutting Room Floor touches only a small number of these records.
- **The community already has a mature, standardized answer to exactly this territory: a "load-after" convention plus an official AI Overhaul Patch Hub, and — more importantly — a hard migration away from record edits toward SPID/SkyPatcher/Synthesis-based package distribution.** For Chronicle, abandon the direct base-record override and distribute your Flee packages via SkyPatcher `packageListAdd` or SPID, or ship a Wrye-Bash-taggable plugin; otherwise you inherit AI Overhaul's well-documented "patch hell."

## Key Findings

1. **AI Overhaul SSE is your direct, unavoidable record-level competitor.** It uses the identical write path you do — editing the NPC base record's AI Data and package list — and it explicitly modifies many of your 19 named NPCs. Its own Nexus FAQ (mod 21654) even lists "Immersive Citizens" under "Not Compatible" and states: "It only edits NPC AI Data & packages. Most other AI mods use the quest alias which will overwrite some behaviors from AIO." This is a "last plugin wins" clash resolvable only by a merge/bashed patch, never silently coexisting.

2. **Immersive Citizens does NOT edit base-record package lists.** It distributes packages through quest aliases (ALPC on quest reference-aliases). Result: no record-level conflict with your override, but a runtime "two masters" conflict where both systems try to command the NPC. This cannot be resolved in xEdit or by load order.

3. **Populated Cities Towns Villages SE (mod 2005) adds exactly 189 new generic NPCs — 28 of them in Whiterun** — each with their own packages; it does not override the vanilla named NPCs' records. (The "193" figure circulating online is from the Legendary Edition build, mod 73147, which lists Riften at 30 rather than 26.) Zero base-record package conflict with your 19.

4. **JK's Whiterun / JK's Skyrim edits cells, navmesh, statics, and idle markers — not NPC package lists.** No base-record package conflict; but your new Flee packages can still misbehave (pathing/navmesh) around JK's rearranged geometry.

5. **Cutting Room Floor edits a limited set of these records.** The official AI Overhaul patch combines "one of the AI Packages from both mods," implying overlap is small but real.

6. **The established community pattern is threefold:** (a) a documented "load after" convention centered on the AI Overhaul SSE - Official Patch Hub; (b) Wrye Bash's `Actors.AIPackages` bash tag, which *merges* package lists rather than dropping them; and (c) a decisive shift toward plugin-free package distribution via SPID, SkyPatcher, and Synthesis patchers.

## Details

### The write path you chose and what it means
Chronicle overrides the `AIPackages` list directly on each NPC's base (`NPC_`) record. In the Bethesda plugin format this is an ordinary Major Record override, governed by the engine's "last-loaded record wins" rule. When two plugins both override the same `NPC_` record, the one later in load order supplies the *entire* winning record's package list; the earlier plugin's package list is not merged — it is discarded. Community documentation states this plainly: Skyrim's engine follows a "last-loaded-record-wins" rule, and "only the last record for an npc is ever used, so multiple patches have multiple records for the same npc and therefore are overwritten by the lowest patch in the load order." This is the core risk for Chronicle.

### Mod-by-mod verdict

**AI Overhaul SSE (Nexus mod 21654, 36,103 endorsements) — DIRECT RECORD CLASH.**
AI Overhaul's own FAQ describes its mechanism as the opposite of alias-based mods: "It only edits NPC AI Data & packages. Most other AI mods use the quest alias which will overwrite some behaviors from AIO." Its changelogs name your NPCs directly: it adds a "Lucia rain spot," "Battleborn Family time and mourn," "Graymane Family mourn," "Danica Water tree after her quest," "Olfina Stoke fire (5pm)," makes "Nazeem now visits Dragonreach on weekdays," "Fixed Lars walking in storms," and "Saffir will follow Amren instead after his quest." Ysolda, Sigurd, Brenuin ("finally sleeps by Whiterun gate"), Heimskr, and Anoriath are all in its scope. Because AIO writes to the same base-record package list you do, **for every overlapping NPC, whichever plugin loads last wins the whole package list and silently drops the other's.** If Chronicle loads after AIO, AIO's entire schedule for that NPC is gone; if AIO loads after Chronicle, your Flee packages never fire. This is patchable — via an xEdit conflict-resolution patch or a Wrye Bash bashed patch with the `Actors.AIPackages` tag — but it is NOT safe to leave unpatched.

**Immersive Citizens - AI Overhaul (Nexus mod 173; one of the most-downloaded AI mods) — RUNTIME CONFLICT, NOT RECORD CLASH.**
IC distributes its AI through quests and quest reference-aliases rather than base-record package edits. A third-party patcher author who reverse-engineered both mods states it precisely: "ICAIO generally uses quests to distribute its AI Packages through quests... AIO on the other hand directly edits the AI in the NPC records. This leads to the potential that these two mods may 'fight' over the NPCs." IC's own documentation (author Arnaud d'Orchymont, ai4egames.com) confirms the priority-based alias design: "Immersive Citizens inject to NPCs an AI with a low priority. Most of time the culprit will be a mod injecting to NPCs an AI with a high priority," and it warns that "SSEedit is not able to detect bad synergies between plugins... The only direct incompatibilities that you may detect with SSEedit are between navmeshes." IC's docs also claim broad compatibility with base-record edits: "Immersive Citizens is compatible with any plugins altering NPCs (inventory, outfit, appearance, faction, etc.)." For Chronicle this means: **no red conflict in xEdit, but a live tug-of-war** — a high-priority alias package from IC can override your Flee package, or your always-running base package can undercut IC's schedule, depending on package priority and conditions. IC covers Whiterun fully; NPCs it explicitly reworks include Nazeem, Adrianne, Lillith, Carlotta, and Heimskr ("Instead of annoying you from 5am to 8pm, Heimskr will only annoy you between 2pm and 6pm"). IC also edits Whiterun navmesh and cells, so it can still break Flee pathing.

**Populated Cities Towns Villages SE (Nexus mod 2005) — NO CONFLICT with your 19.**
PCTV's own page tally reads "WHITERUN (28 new NPCs) ... TOTAL NEW GENERIC NPCs: 189" (its prose loosely says "about 200"). Each is "respawnable, with own AI package and daily action." It does not override vanilla named NPCs' records. Its author states "PCTV is compatible with everything." No base-record package overlap with your 19. It also appears under "Compatible" in AI Overhaul's own FAQ.

**JK's Whiterun / JK's Skyrim (Nexus mod 6289) — NO base-record package conflict; navmesh/pathing risk only.**
JK's is a city overhaul touching cells, statics, navmesh, and idle markers. The dedicated "JKs Skyrim - AI Overhaul SSE Patch" (mod 34194, 9,285 endorsements) exists only because JK's "moves idle markers." Its author confirms in the posts tab: "Yes, this moves idle markers. Synthesis is for ai packages getting applied to npcs," and "this mod only moves idle markers to their proper spots"; the same thread notes "The AI Overhaul Skypatcher... only affects AI packages but doesn't move the markers. You still need this patch." So JK's does not overwrite your `AIPackages` lists, but your Flee packages may send NPCs into JK's rearranged geometry, causing them to get stuck — the same class of issue users report ("NPCs are getting stuck at the bannered mare steps").

**Cutting Room Floor (Nexus mod 276) — SMALL record overlap, cleanly patchable.**
The AI Overhaul Official Patch Hub notes: "CRF should be loaded before AIO. Patch combines one of the AI Packages from both mods. All conflicts resolved." CRF also restores scenes involving Amren, Adrianne, and Fralia (its changelog: "The argument scene between Olaf and Vignar should now only trigger after Armen, Adrianne, and Fralia have all had their scenes with the Battle-Borns"). Where CRF overrides one of your 19 records, it is an ordinary last-wins clash, resolvable via the same merge-patch approach as AIO.

### Is the conflict "silent drop" or "patchable"?
Both, sequentially. Left alone, two base-record overrides of the same NPC produce a *silent* drop of the loser's package list (last wins). It becomes *patchable* the moment you either (a) build an xEdit conflict-resolution patch that forwards the desired package list, or (b) build a Wrye Bash bashed patch and ensure the contributing plugins carry the `Actors.AIPackages` bash tag. That tag is the key nuance: Wrye Bash's AI Packages importer "merges the AI Packages so that they are all present from all tagged mods," rather than letting one win. It is now supported for Skyrim SE (previously Oblivion-only). This is the cleanest "merge patch" route for a plugin like Chronicle. Note the Immersive Citizens exception: because IC is alias-based, neither an xEdit CR patch nor a bashed patch resolves it — that conflict is purely runtime.

### The established community convention for this exact territory
This is extremely well-trodden ground because AI Overhaul's package-distribution model created years of "patch hell." The community's canonical responses:

- **The AI Overhaul SSE - Official Patch Hub (mod 35823, 11,241 endorsements)** codifies a "load after" convention: mods like CRF and RDO are "loaded before AIO," AIO "combines AI Packages" via distributed official patches, and there is a curated list of third-party patches (JK's, Cities of the North, etc.).
- **Wrye Bash `Actors.AIPackages`** for merging package lists in a bashed patch.
- **Synthesis AI Overhaul Patcher (Excinerus, and sincerity21's fork)** — a Mutagen-based patcher that automatically "Forwards Packages from AIO, keeps packages added by later loaded mods that were not removed by USSEP or AIO." This is the modern automated equivalent of what Chronicle would otherwise force users to do by hand. (Notably, this is the same Mutagen stack Chronicle already builds on.)
- **SPID / SkyPatcher distribution (AI Overhaul SSE SPIDified, mod 136826; AI Overhaul SSE SkyPatcher Patch, mod 138722)** — these reissue AIO's packages via Spell Perk Item Distributor and SkyPatcher `.ini` files, which apply packages at runtime *without* editing the base record, thereby "absolving many incompatibilities." AIO's SPIDified author summarizes the whole problem: "AI Overhaul SSE is a great mod. But its Achillesheel is the distribution of its packages to npcs. So dozens of patches are needed to solve distribution and conflicts."

## Recommendations

**Stage 1 — Reconsider the write path (do this first).** Your current design (direct `AIPackages` base-record override) puts Chronicle in direct, silent conflict with AI Overhaul SSE across most of your 19 NPCs, and replicates the exact "Achilles heel" the community spent years engineering around. Since your packages are Flee-type, gated by a global, and you already call `EvaluatePackage` at runtime, you are an ideal candidate for **additive, non-record distribution**:
   - **Preferred: SkyPatcher `packageListAdd`.** Distribute each Flee package via a SkyPatcher `.ini` targeting each NPC's FormID. This adds your package to the NPC's runtime package stack without overriding the base record — so AI Overhaul, CRF, and any NPC replacer keep their record edits, and there is no last-wins clash. Conflicts between SkyPatcher inis resolve by folder name, not plugin load order.
   - **Alternative: SPID** if you prefer keyword/faction-based distribution.
   These approaches eliminate the AI Overhaul record clash entirely and sidestep the merge-patch burden. Because you author with Mutagen already, you can generate the SkyPatcher inis headlessly from the same pipeline.

**Stage 2 — If you keep the direct base-record edit**, then adopt the community convention explicitly:
   - Add the `Actors.AIPackages` bash tag to Chronicle's plugin header (or submit it to the LOOT masterlist) so Wrye Bash users get an automatic *merge* of your Flee packages with AIO's schedules instead of a drop.
   - Publish a **Chronicle – AI Overhaul patch** and a load-order rule ("load Chronicle after AI Overhaul, then let the bashed/Synthesis patch merge"), mirroring the Patch Hub pattern. Consider shipping a Synthesis patcher, since Excinerus/sincerity's AIO patcher already demonstrates the forward-and-merge logic you'd need — and you can reuse Mutagen.
   - Document that your packages must sit at an appropriate priority in the merged list for the Flee behavior to actually win when the global is set.

**Stage 3 — Handle Immersive Citizens separately.** Because IC is alias-based, no merge patch helps. Two options: (a) document that Chronicle's Flee packages should be authored at a priority/condition that beats IC's low-priority alias injection when your global is active; or (b) use IC's own opt-out mechanism (its exclusion faction) for the 19 NPCs so IC yields to Chronicle in Whiterun. Test in-game with `RefScope`/console `evp`, since xEdit will show no conflict.

**Stage 4 — Navmesh/pathing QA with JK's Whiterun and IC.** Even with distribution solved, verify Flee destinations against JK's rearranged Whiterun geometry and IC's redesigned navmesh to avoid stuck-NPC reports.

**Benchmarks that change the plan:**
- If you switch to SkyPatcher/SPID, you can drop Stage 2 entirely — no bash tag, no AIO patch needed.
- If telemetry/user reports show NPCs ignoring Flee when the global is set, the cause is almost always priority ordering (in a bashed/merged plugin) or IC alias override — revisit Stages 2–3.
- If you stay plugin-based and users run Wrye Bash, the `Actors.AIPackages` tag is the minimum bar; without it, expect bug reports of "AI Overhaul schedules broke" or "NPCs don't flee."

## Caveats
- Exact per-NPC overlap between Chronicle's 19 and each mod requires opening the plugins in SSEEdit; the mod changelogs confirm AIO touches a large majority of your list but do not enumerate all 19. Amren, Anoriath, and Danica are covered by IC's Whiterun overhaul by inference (named unique NPCs in a fully-overhauled zone) rather than explicit changelog citation.
- IC's "compatible with any plugins altering NPCs" claim is the author's; it is true for record-level *coexistence* but does not mean the *runtime behavior* will be what you intend when two systems command the same NPC.
- Wrye Bash `Actors.AIPackages` support for SSE is confirmed in the Wrye Bash issue tracker; verify it functions on your current Wrye Bash build before relying on it, as importer behavior has had bugs historically.
- Endorsement counts (AIO 36,103; Patch Hub 11,241; JK's-AIO patch 9,285) are from the respective Nexus mod pages as of mid-2026; download totals were not retrievable from live Nexus stats in this research. The "~2.8M" Immersive Citizens download figure circulating on secondary sites could not be confirmed against Nexus directly and is omitted from the findings.
- Some cited community pages (e.g., christopherqueenconsulting, oreateai) are secondary aggregators; the mechanism claims here are corroborated by primary sources (mod pages, ai4egames.com, GitHub patcher READMEs, Wrye Bash docs).
