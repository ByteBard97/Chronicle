# Prior Art for a Social-Simulation Debug Dashboard: Causality, Time-Travel, Lineage, Run-Comparison, and Small-Scale Graph Inspection

## TL;DR
- For belief provenance, copy **Pernosco's** click-a-value → dataflow chain (clicking a value opens a "Dataflow" panel that walks backward through every write to its origin); for mutating rumors, copy **Nextstrain/Auspice** (mutations rendered directly on tree branches, colorable by geography/time); for two-run diffs, copy **ESMValTool's** 4-panel difference layout (run A, run B, then A−B rendered as a first-class panel) combined with **pytest-benchmark's** signed Δ columns and **Chromium's** bisection to the first diverging point; for social-graph deltas across ticks, copy **GraphDiaries** (staged animated transitions with red halos on removed elements, blue halos on added, plus a layout-stability slider).
- The single most important cross-cutting rule: **keep node positions stable across ticks.** Force-directed layouts jitter and "wobble" on every data update because d3-force re-initializes new nodes at random positions, which destroys the user's mental map — pin positions and only animate genuinely changed elements.
- Performance is comfortable for your 25–1,000 NPC scale in SVG/Canvas for the graph view (Canvas degrades noticeably only at ~3,000–5,000 nodes), but the 1,000-marker map god-view with overlays should use Canvas/WebGL rather than thousands of SVG DOM nodes.

## Key Findings

### (1) Causality/trace drill-down → belief provenance chains
- **Jaeger/Zipkin** render traces as a span tree / waterfall: spans are colored by service, nested to model causal (parent-child) relationships, and clicking a span reveals its parent/children. This is the proven "walk from effect to cause" interaction.
- **Span references / OpenTelemetry span links** are the key transfer for provenance that is a DAG, not a tree. Jaeger's data model has references with required types (`child-of`, `follows-from`); OpenTelemetry links are typeless but carry attributes and can point across traces. Jaeger's UI shows these in a "references" section where you click "span from another trace" to jump. Documented pain point: Jaeger arbitrarily picks one reference as the tree parent and shows *no visual relationship* for non-primary references (jaeger-ui issue #299) — a warning for belief chains where "X ← told by Y ← Y witnessed Z" may have multiple causes.
- **Perfetto** computes and highlights the critical path ("Critical path lite" button lists the threads/steps that led to a state change), so the user doesn't have to manually follow "woken by" links. It requires specific events (sched_switch/sched_waking) to be present or the button is hidden.
- **Pernosco is the strongest example to copy.** Clicking a displayed value opens a "Dataflow" view that shows where the value came from; when a value was copied, Pernosco displays the copy step and *automatically continues backward*, skipping trivial copies, and can even track data backward through pipes/sockets. This is almost exactly "NPC believes X ← told by Y ← Y witnessed event Z": each hop is a copy/transformation of a belief, and the UI auto-walks the chain. Pernosco pairs this with a "Notebook" for annotating points in time and an "Alerts" panel that auto-focuses the most interesting event. Docs: https://pernos.co/about/dataflow/

### (2) Time-travel debugging UIs → the timeline scrubber + inspectors
- **Redux DevTools** is the canonical action-log + jump-to-state design: a left-hand action log; per-action **Jump** (set app state to the moment after that action) and **Skip** (recompute state as if the action never fired); a **Diff** tab that shows *only what that action changed* in the state tree; and a time-travel slider. Documented limitation directly relevant to you: components can re-dispatch actions/side-effects during time travel unless the app is pure (zalmoxisus/redux-devtools-extension #685) — your headless sim must treat replay as pure state reconstruction.
- **rr/Pernosco** add reverse execution and dataflow (covered above). Pernosco's "Alerts" panel auto-surfaces the most "interesting" points (e.g., a crash) as initial focus — analogous to auto-focusing a grudge formation or a rumor mutation.
- **Replay.io** contributes several patterns: rewind/fast-forward to each execution of a line via a "Print Statement" timeline; a **function timeline** to scrub within one function's execution across branches/loops; a **React panel** that shows component props/state/hooks at a moment and **highlights values that changed since the prior render in yellow**; and comments as "pins" at a point in time. The React Timeline is explicitly a proof-of-concept relying on React internals — a caution about coupling your inspector too tightly to internal state shapes. Docs: https://docs.replay.io/reference-guide/debugger/breakpoints
- **Event-sourcing dashboards** map cleanly to your tick model. **Temporal's Web UI** shows an Event History (a complete durable log), groups related events into "Event Groups" (e.g., ActivityTaskScheduled/Started/Completed) with high-value summaries, and a **Timeline view** representing the flow of events in time; it reconstructs state by replaying events from the beginning (or a cached snapshot). Temporal's determinism requirement — replay must produce identical state — is the exact contract your "render as of tick T" views need. Docs: https://docs.temporal.io/encyclopedia/event-history , https://temporal.io/blog/lets-visualize-a-workflow

### (3) Lineage/mutation trees → rumor variants
- **Git graph layouts**: GitKraken draws branches as straight lanes; SmartGit/Git Extensions use curved branches; gitk reorders commits for compactness (order does not follow dates). The documented failure mode is "spaghetti" when many branches interleave; straight-lane assignment (GitKraken) and "solo/opt-in" branch filtering are the mitigations. GitHub's network graph and gitgraph.js are lightweight but degrade with many concurrent branches. Reference: https://pvigier.github.io/2019/05/06/commit-graph-drawing-algorithms.html
- **Nextstrain/Auspice is the strongest example for mutating rumors.** It renders a phylogenetic tree where **mutations are placed directly on the branches** (hover a branch to see how many/which mutations), and the same tree is re-colorable by clade, geography, time, or genotype at a position, with a linked map and a divergence-vs-date view. This is precisely "a rumor mutated here, and here's the variant that resulted, and where/when it spread." Documented performance behavior, per the Auspice changelog: *"Performance improvement: We no longer attempt to animate actions on trees with over 4000 tips which results in more responsive interactions."* Drawing performance scales with node count, and Auspice uses desaturation to convey (lack of) confidence — all directly reusable. Docs: https://docs.nextstrain.org/projects/auspice/en/stable/
- **Misinformation/rumor-spread visualizations**: Vosoughi, Roy & Aral, "The spread of true and false news online," *Science* 359(6380):1146–1151 (Mar 9, 2018) — *"The data comprise ~126,000 stories tweeted by ~3 million people more than 4.5 million times"* from 2006–2017 — characterize cascades by depth, breadth-at-depth, and structural virality, the metrics to display per rumor. **Hoaxy** renders diffusion networks (nodes = accounts, edges = retweets/mentions/replies/quotes) plus a timeline plot of tweet volume; it was retired July 2025 and folded into OSoMeNet. The **Allport & Postman** tradition (leveling, sharpening, assimilation) is the theoretical model for *how* your rumors mutate: leveling = detail loss, sharpening = selective retention, assimilation = distortion toward the hearer's biases — these are exactly the mutation operators to visualize on branches. Refs: https://www.science.org/doi/10.1126/science.aap9559 , https://journals.plos.org/plosone/article?id=10.1371%2Fjournal.pone.0196087
- **Textual diff presentation**: the proven pattern is line-level diff first, then a secondary word-level diff on paired changed lines (how GitHub's PR view and Google's diff-match-patch both work; diff-match-patch implements Myers' algorithm and powers Google Docs). Word-level highlighting is best for small edits (a single changed word "lights up"); side-by-side is best for large changes; inline/unified is most compact. Documented pitfall: inline diff view can obfuscate intra-line changes that side-by-side reveals (GitLab issue #24684). Wikipedia's diff marks moved lines with curved arrows; wikEd diff additionally detects block moves at word/character level. Docs: https://github.com/google/diff-match-patch/wiki/Line-or-Word-Diffs

### (4) Run/branch comparison → diffing two simulation runs
- **Jaeger trace comparison (since 1.7)** condenses each trace into a tree of unique service/operation paths and color-codes structural differences: dark red = node only in trace A, dark green = only in trace B, light red/green = present in both but different span counts, gray = identical. Documented bug: a node can show as both added and removed under the same parent when only a child differs (jaeger-ui #252) — a warning that your diff's grouping key matters. A latency-diff mode was demoed at KubeCon '18 but stalled unmerged (jaeger-ui #513). Ref: https://medium.com/jaegertracing/trace-comparisons-arrive-in-jaeger-1-7-a97ad5e2d05d
- **ESMValTool is the strongest cross-domain "diff two runs" precedent.** Its canonical layout is a 4-panel difference map: run A and run B on the top row, and the **A−B difference rendered as its own panel** on the bottom. It uses **stippling/hatching to mark where the difference is statistically significant vs. where runs agree** — directly analogous to shading the ticks/agents where two sim runs agree vs. diverge. Its purpose statement explicitly frames "compare a new model version against a previous version" as first-class. Docs: https://esmvaltool.org/about/ , https://docs.esmvaltool.org/en/latest/recipes/recipe_oceans.html
- **pytest-benchmark** shows run-to-run regression as **signed Δ columns**: `--benchmark-compare` adds a differences row; `--between` produces a pivot where the first source is the cyan reference and each later source gets a `Δ` column; `--benchmark-compare-fail=min:5%` fails the suite past a threshold. **Chromium Perf Dashboard** plots time-series with automated anomaly alerts (exclamation icon at the change point), threshold-based `improve`/`regress` expectations with a `better: lower/higher` direction, a "before" reference column with `Δavg`, sorting by magnitude of change, and Pinpoint bisection to find the *first* diverging commit. Docs: https://pytest-benchmark.readthedocs.io/en/latest/comparing.html , https://chromium.googlesource.com/chromium/src/+/lkgr/docs/speed/addressing_performance_regressions.md
- **NetLogo BehaviorSpace** has no built-in diff UI — it exports CSV, and its "Spreadsheet output" aligns runs vertically by `[step]` so runs line up for comparison; it leaves later step cells blank when one run stops early. Third-party tools (analyzeBehaviorspace Shiny app, nlrx R package) add the actual comparison UI. Docs: https://docs.netlogo.org/behaviorspace.html
- **Game replay/ghost overlays**: LiveSplit compares against a designated "comparison" run with per-split deltas colored green (ahead) / red (behind) / gold (new best segment); the delta only "starts ticking" once you pass the comparison's split. TrackMania ghosts overlay a prior run *spatially* so you see exactly where two runs physically diverge, with checkpoint-based delta computation and re-sync at each checkpoint. Docs: https://livesplit.org/ , https://openplanet.dev/plugin/huntingstats

### (5) Graph inspection at 20–100 nodes (up to 1,000)
- **Layout stability is the central problem.** d3-force re-initializes new nodes at random positions, producing a "huge wobble at load time" and jitter when nodes crowd. Mitigations: set `fixed`/fx-fy to pin positions; use `alphaTarget` to smooth transitions; continue the simulation from current positions rather than restarting; custom attract forces to pull nodes to assigned slots. The core research finding (Beck et al., *A Taxonomy and Survey of Dynamic Graph Visualization*, Computer Graphics Forum): dynamic graphs are shown either as **animation (time-to-time)** or **timeline/small-multiples (time-to-space)**; animation's main goal is mental-map preservation by keeping node positions stable, but minor topology changes (e.g., linking two components) can massively perturb a force layout. Refs: https://d3js.org/d3-force/simulation , https://www.visus.uni-stuttgart.de/documentcenter/forschung/visualisierung_und_visual_analytics/eurovis14-star.pdf
- **Animation vs. small multiples**: Empirical results (Archambault & Purchase; Robertson et al.; Boyandin et al.) show animation is engaging and good for *adjacent* time steps but less accurate for trend analysis over many steps; small multiples are faster and let users spot patterns spanning longer periods. Saraiya et al.: animation better for two time points, timeline better for many. **GraphDiaries is the strongest delta-highlighting example** (Bach, Pietriga & Fekete, IEEE TVCG 20(5):740–754, 2014, DOI:10.1109/TVCG.2013.254): staged animated transitions render removal (red halos) → layout adaption → addition (blue halos), plus small-multiple thumbnails on a timeline, a **layout-stability slider** (no movement ↔ full re-layout), and difference highlighting; the user study *"compares GraphDiaries to existing techniques for temporal navigation in dynamic networks, showing that it outperforms them in terms of both task time and errors for several of these tasks."* PDF: https://aviz.fr/~bbach/graphdiaries/Bach2013GraphDiaries.pdf
- **Edge-type legibility**: encode multiple edge types (belief-source, grudge, told-by) with color + dash + width; node-link diagrams become cluttered past ~hundreds of edges, so at your scale keep edge counts per view low and use delta-highlighting (fade unchanged, highlight added/removed) rather than showing all edges at all ticks.
- **Performance with hundreds of entities**: Canvas-based renderers (Cytoscape.js, vis-network) degrade noticeably at ~3,000–5,000 nodes on the main thread; Sigma.js/WebGL raises the practical ceiling to ~100,000–500,000 nodes. Concrete benchmark, per the Cytoscape.js blog "WebGL Renderer Preview" (Jan 13, 2025), tested on an M1 MacBook Pro in Chrome: an EnrichmentMap network with ~1,200 nodes and 16,000 edges "runs at about 20 FPS with the canvas renderer but speeds up to over 100 FPS with the WebGL renderer," and a network with ~3,200 nodes and 68,000 edges "crawls at 3 FPS with the canvas renderer but improves to 10 FPS with the WebGL renderer." At 25–1,000 NPCs you are safely inside Canvas territory for the graph; SVG is fine at the low end but avoid thousands of SVG DOM nodes. Cytoscape.js's COSE layout runs synchronously and blocks the UI above a few thousand nodes — a reason to precompute/pin layouts. Ref: https://blog.js.cytoscape.org/2025/01/13/webgl-preview/

## Details

**Belief provenance (map Pernosco).** Model each belief as a node with a "dataflow" of provenance edges (`told-by`, `witnessed`, `inferred-from`). Clicking a belief in the per-NPC inspector should open a provenance panel that walks backward hop by hop, auto-collapsing trivial relays (verbatim repeats) the way Pernosco skips trivial copies, and stopping at "origin" events (an NPC directly witnessing event Z). Because provenance is a DAG with multiple causes, avoid Jaeger's mistake of hiding non-primary parents: render all causal references, and when a belief has multiple sources, show them as sibling branches rather than picking one. Borrow Perfetto's critical-path idea to offer a "why does this NPC believe this" one-click highlight of the dominant provenance chain.

**Timeline scrubber (map Temporal + Redux DevTools).** Your "as of tick T" contract is event-sourcing: store an append-only event log and materialize state at T by replay (with periodic snapshots for speed, as Temporal caches). The global scrubber is the Redux time-travel slider; the per-NPC inspector's "what changed at this tick" is the Redux Diff tab (show only the delta). Group low-level events into Temporal-style "Event Groups" (e.g., rumor-heard / rumor-mutated / rumor-retold as one group) so the timeline isn't a wall of atomic events. Enforce determinism: replaying to T must yield identical state, or your views will disagree.

**Rumor lineage (map Auspice).** Represent each rumor as a tree whose branches carry the mutations (leveling/sharpening/assimilation edits) that occurred as it passed between NPCs. Put the word-level text diff of the statement *on the branch* (or in a branch-hover card), computed line-then-word with diff-match-patch. Make the same tree re-colorable by NPC faction, town district, or tick — Auspice's killer feature. For the "cascade" view of who-told-whom, use a Hoaxy-style diffusion network as an alternate layout of the same data.

**Two-run diff (map ESMValTool + pytest-benchmark + LiveSplit).** Align both runs by tick (BehaviorSpace's `[step]` alignment; handle unequal-length runs by blanking later ticks). Present three panels: run A state, run B state, and the **difference as a first-class panel** (ESMValTool). In tabular NPC/rumor comparisons, use signed Δ columns with a designated baseline run (pytest-benchmark's cyan reference), color deltas green/red (LiveSplit), and let the user set a threshold that flags divergence. Most important: compute and jump to the **first tick where the two runs diverge** (Chromium's bisection / Pinpoint pattern; LiveSplit's "delta starts ticking at divergence"), and offer a spatial overlay on the map god-view showing which NPCs/edges differ (TrackMania ghost overlay). Determinism via a stored seed + event log makes an exact tick-aligned diff possible.

**Social-graph deltas (map GraphDiaries).** Pin node positions across ticks (d3-force fx/fy or a precomputed layout) and expose GraphDiaries' layout-stability slider so the user trades stability vs. optimal layout. On stepping T1→T2, run the staged transition: fade/red-halo removed edges, adapt layout, blue-halo added edges. Offer both animation (adjacent ticks) and small-multiples (many ticks) per the empirical guidance. Encode the three edge types with color+dash+width, and by default fade unchanged edges so only the delta is salient.

## Recommendations
1. **Belief provenance drill-down → copy Pernosco's dataflow panel.** Build a click-value-→-walk-backward panel with auto-collapse of trivial relays and multi-parent (DAG) rendering. Avoid Jaeger's single-parent flattening (jaeger-ui #299). Docs: https://pernos.co/about/dataflow/ , https://www.jaegertracing.io/docs/1.76/architecture/
2. **Rumor lineage → copy Nextstrain/Auspice.** Mutations on branches, re-colorable by geography/time, word-level text diff via diff-match-patch on each branch. Disable animation above ~4,000 variants (Auspice's own documented threshold). Docs: https://docs.nextstrain.org/projects/auspice/en/stable/ , https://github.com/google/diff-match-patch/wiki/Line-or-Word-Diffs
3. **Two-run comparison → copy ESMValTool's difference-panel layout + pytest-benchmark Δ columns + Chromium bisection.** Render A, B, and A−B; align by tick; auto-locate the first divergence tick; threshold-flag deltas; overlay differences spatially. Docs: https://esmvaltool.org/about/ , https://pytest-benchmark.readthedocs.io/en/latest/comparing.html , https://chromium.googlesource.com/chromium/src/+/lkgr/docs/speed/addressing_performance_regressions.md
4. **Social-graph deltas across ticks → copy GraphDiaries.** Staged transitions (red halos removed, blue halos added), layout-stability slider, small-multiples timeline; pin positions to preserve the mental map. Paper/PDF: https://aviz.fr/~bbach/graphdiaries/Bach2013GraphDiaries.pdf ; survey: https://www.visus.uni-stuttgart.de/documentcenter/forschung/visualisierung_und_visual_analytics/eurovis14-star.pdf
5. **Rendering stack.** Use Canvas (or Cytoscape.js/Sigma.js) for the graph view; you are far below the ~3,000–5,000-node Canvas ceiling, so SVG is acceptable at the low end but switch to Canvas/WebGL for the 1,000-NPC map god-view with overlays. Precompute/pin layouts to avoid Cytoscape COSE's synchronous main-thread blocking and d3-force's load-time wobble. Benchmark with your real node/edge density before committing. Docs: https://blog.js.cytoscape.org/2025/01/13/webgl-preview/ , https://d3js.org/d3-force/simulation

**Thresholds that change these recommendations:** If a single tick's graph ever exceeds ~3,000 simultaneous edges, drop SVG entirely and adopt Sigma.js/WebGL. If rumor trees exceed ~4,000 variants, disable transition animations (Auspice's own threshold). If provenance chains routinely have >1 cause per hop, prioritize the DAG-rendering work early, since the tree-flattening shortcut will actively mislead.

## Caveats
- The Jaeger latency-diff mode remains a stalled proof-of-concept (jaeger-ui #513); don't assume a turnkey latency-diff exists — the merged feature is the *structural* comparison.
- Replay.io's React Timeline is explicitly a proof-of-concept tied to React internals; treat any "framework-aware" state inspector as fragile against internal changes.
- Hoaxy was retired July 2025 (now OSoMeNet); cite it as a design precedent, not a live tool.
- Empirical animation-vs-small-multiples results are task-dependent (animation wins for adjacent-step tasks, small multiples for long-span trend tasks); offer both rather than betting on one.
- Node-count performance figures are hardware- and density-dependent; the ~3,000–5,000 (Canvas) and ~100,000–500,000 (WebGL/Sigma) numbers are practical ceilings from vendor/community benchmarks, not guarantees — benchmark your own graph shape.
- NetLogo BehaviorSpace has no native diff GUI; the "spreadsheet output aligns runs by step" affordance is the closest built-in comparison feature, with real comparison done in external tools.
