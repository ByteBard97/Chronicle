# Skyrim Dynamic-Speech Lip Sync Feasibility

**Date:** 2026-09 (report's own header: "Prepared September 2026")
**Method:** 1 external research pass (Kimi) — the deep, independent companion pass on the
original Prompt 38 brief (report 41 was Gemini's pass on the same brief, filed first). See

**Filing note:** this report reaches a **different primary recommendation than report 41**.
Report 41 (Gemini) frames Mantella's native-`.lip`-file generation (via FaceFXWrapper) as the
main proven path. This report, after auditing Mantella's actual source at commit level, agrees
FaceFXWrapper/native-`.lip` works but recommends **against** it as Chronicle's default —

(SkyrimNet's approach), reserving native `.lip` generation as a Windows compatibility fallback
only. Read both; this one is more decision-actionable for Chronicle specifically.

## 1. Executive decision

**Chronicle does not need to invent lip sync from scratch, but it should not ship close-up audible NPC dialogue with a completely frozen mouth as its intended v1 presentation.** Runtime lip sync for synthesized speech in Skyrim is a solved problem in two independent ways, both deployed in production mods today: native `.lip` file generation after TTS (Mantella's pipeline, built on Bethesda's `LipGenerator.exe` with Nukem9's `FaceFXWrapper` as fallback) and procedural phoneme-driven facegen animation through Mfg Fix NG (SkyrimNet's approach, with the 2023 Inworld mod as earlier source-available precedent) ([Mantella ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)) ([SkyrimNet-GamePlugin discussion #423](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/423)).

The honest-v1 question therefore is not "can we solve lip sync?" but "which existing solution fits Chronicle's constraints?" The recommendation developed in this report:

| Priority | Route | Role for Chronicle v1 |
|---|---|---|
| Default | **Procedural mouth animation via Mfg Fix NG** (Path B) | Ship this. Cross-platform, no proprietary assets, no per-line generation latency; demonstrated at production quality by SkyrimNet's "Lipsync Overhaul" release ([SkyrimNet-GamePlugin discussion #423](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/423)) |
| Compatibility fallback | **Mantella-style native `.lip` generation** via LipGenerator → FaceFXWrapper (Path A) | Offer on Windows installs where the Creation Kit's LipGen tools or `FonixData.cdf` are present; this is the most ecosystem-proven route but is Windows-bound and license-encumbered ([FaceFXWrapper README](https://github.com/Nukem9/FaceFXWrapper)) |
| Research track | **OpenFaceFX clean-room `.lip` writer** (Path C) | Track and contribute to in-game verification; adopt only after its slot→morph map is calibrated in the actual engine, which the authors explicitly mark as unresolved ([OpenFaceFX compatibility documentation](https://openfacefx.com/docs/COMPATIBILITY/)) |
| Failure mode only | **Audio with frozen mouth** (Path D) | Acceptable for debugging, off-screen voices, narration, and subtitles-only play; not validated as an acceptable default for first-person face-to-face dialogue, where frozen mouths are treated by players as a bug to be fixed ([Nexus Forums: NPC mouths not moving while talking](https://forums.nexusmods.com/topic/7283886-npc-mouths-not-moving-while-talking/)) |

## 2. The question and Chronicle's constraints

Chronicle is a Skyrim SE/AE mod backed by an external social-simulation service; its voice tier lets an LLM render one grounded dialogue line per interaction, synthesizes it with a TTS model, and plays the audio on an NPC or the player character in-game. The perceived blocker is that Skyrim's dialogue presentation expects per-audio-file lip-sync data, which conflicts with speech synthesized at runtime.

This report answers the six sub-questions posed in prompt 38:

1. Does any existing Skyrim mod solve runtime TTS plus lip sync without pregenerated assets? — **Yes, at least two: Mantella (runtime `.lip` generation) and SkyrimNet (procedural phoneme animation)** ([Mantella repository](https://github.com/art-from-the-machine/Mantella)) ([SkyrimNet-GamePlugin repository](https://github.com/MinLL/SkyrimNet-GamePlugin)).
2. What exactly does Mantella do for lip movement? — **Runtime external generation of native `.lip` files**, detailed in §5 ([Mantella ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)).
3. Can open-source tooling generate `.lip` headlessly from audio plus text, fast enough for runtime? — **Yes: FaceFXWrapper (proprietary-data-dependent) and experimentally OpenFaceFX (clean-room)**, detailed in §6.
4. Can that tooling run outside Windows or without the Creation Kit? — **Without the CK, yes (FaceFXWrapper's purpose); outside Windows, only via Wine or via the unverified OpenFaceFX writer**, detailed in §6 ([FaceFXWrapper README](https://github.com/Nukem9/FaceFXWrapper)) ([Mantella ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)).
5. Is audio-only/no-lip-movement acceptable in practice? — **For unvoiced dialogue a placeholder lip file is an accepted community fallback (Fuz Ro D-oh); for audible close-up speech, frozen mouths are reported and treated as bugs**, detailed in §8 ([Fuz Ro D-oh, Skyrim Special Edition Nexus](https://www.nexusmods.com/skyrimspecialedition/mods/15109)).
6. What is realistic runtime `.lip` latency versus accepting no lip movement for v1? — **≈0.5 s per affected line in Mantella's shipped pipeline; millisecond-scale in our OpenFaceFX benchmark but without verified in-game output**, detailed in §9 ([Mantella real-time NPCs guide](https://art-from-the-machine.github.io/Mantella/pages/real_time_npcs.html)).

## 3. How Skyrim actually plays voiced dialogue

Understanding the native pipeline matters because every runtime solution is a way of feeding it — or of bypassing it.

**The asset pair.** In Skyrim's data layout, a voiced dialogue response is an audio file plus a same-named `.lip` file containing FaceFX facial-animation curves; the two can ship loose (WAV + LIP) or packed together in a `.fuz` container, and third-party tooling treats "create the `.lip` (and optionally pack the `.fuz`) alongside the `.wav`" as the standard post-synthesis step ([lip and .fuz plugin for xVASynth, Nexus Mods](https://www.nexusmods.com/skyrimspecialedition/mods/55605)). FaceFXWrapper's documented interface — game type, language, `FonixData.cdf`, source WAV, output `.lip`, and the dialogue text — mirrors exactly what the Creation Kit's FaceFX integration consumes ([FaceFXWrapper README](https://github.com/Nukem9/FaceFXWrapper)).

**The engine side is FaceFX-aware, not FaceFX-optional.** Skyrim's engine deliberately delays some dialogue lines so the FaceFX integration has time to morph the face before audio starts; the infamous post-patch-1.9 "lip sync bug" was this intentional delay being multiplied, and it was reproducible per-line and fixed by a community patch — evidence that lip timing is a first-class engine behavior, not cosmetic garnish ([AFK Mods: Skyrim Lip Sync Bug — Finally Fixed](https://www.afkmods.com/index.php?/topic/4473-skyrim-lip-sync-bug-finally-fixed/)). Conversely, when facial animation fails to trigger at all (a known engine issue in actor-heavy scenes), players file it as a bug with videos and reproduction steps ([Engine Fixes for Skyrim SE, issue #7](https://github.com/aers/EngineFixesSkyrim64/issues/7)).

**The authoring tools are the constraint.** The official generation path is `LipGenerator.exe`, which ships with the Skyrim SE Creation Kit under `Tools\LipGen\` alongside `LIPFuzer.exe` ([SteamDB: Skyrim SE Creation Kit update, 5 Dec 2023](https://steamdb.info/patchnotes/12865886/)). These binaries are Bethesda-licensed and must not be redistributed; third-party GUI wrappers explicitly exclude `LipGenerator.exe` and `FonixData.cdf` from their downloads and instruct users to source them from their own CK installation ([Lip Generator GUI, Nexus Mods](https://www.nexusmods.com/skyrimspecialedition/mods/172869)). The manual CK workflow is laborious enough that mod authors publish step-by-step laments about it, which is precisely the friction runtime pipelines eliminate ([Nexus Forums: Can't generate .LIP files](https://forums.nexusmods.com/topic/5390780-le-cant-generate-lip-files/)).

The practical consequence for Chronicle: **the runtime problem is not "make Skyrim animate lips" — the engine already does that whenever valid lip data is present — but "produce valid lip data (or an equivalent facegen drive signal) at runtime, headlessly, on Chronicle's platform."**

Two further points complete the landscape. First, the xVASynth ecosystem — the dominant offline voice-synthesis toolchain for Bethesda mods — treats `.lip`/`.fuz` creation as an automatic post-processing plugin step with no Creation Kit involvement, which normalized "audio without lip data is an incomplete asset" as the community default ([lip and .fuz plugin for xVASynth](https://www.nexusmods.com/skyrimspecialedition/mods/55605)). Second, the newer Pantella pipeline and xVASynth's own plugin both integrate through the same FaceFXWrapper binary, making that tool the de-facto integration point for the entire runtime-.lip ecosystem ([OpenFaceFX compatibility survey](https://openfacefx.com/docs/COMPATIBILITY/)).

## 5. What Mantella actually does for lip movement

Prompt 38's second question deserves an exact answer, because Mantella is the most-cited system in this space and is frequently misdescribed. The answer from audited source: **Mantella performs runtime external generation of native, FaceFX-compatible `.lip` files — not procedural animation, and not no-sync.** The pipeline, step by step:

**Step 1 — Synthesize.** A TTS backend produces the voiceline WAV. Mantella supports local Piper, xVASynth, and XTTS, plus external providers, selected in its configuration UI ([Mantella installation guide](https://art-from-the-machine.github.io/Mantella/pages/installation.html)).

**Step 2 — Generate the lip file, conditionally.** After synthesis, Mantella decides whether to generate lip data based on the user setting `Text-to-Speech → Lip File Generation`, whose options are `Enabled`, `Lazy`, and `Disabled`; the setting's own description says disabling improves response times and that `Lazy` skips lip syncing "only for the first sentence spoken of every response" ([tts_definitions.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/config/definitions/tts_definitions.py)). The code implements exactly that: lip generation runs when the mode is `Enabled`, or when the mode is `Lazy` and the line is not the first of the response ([ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)).

**Step 3 — Try the official tool, then the community tool.** The generation function's docstring states it "Generates .lip files for voicelines using Bethesda's LipGen tool with FaceFXWrapper as fallback" ([ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)). Mantella first invokes `LipGenerator.exe` from the configured game folder with the WAV path, the exact dialogue text, a language parameter, and an `-Automated` flag; its setup UI tells users to install the Creation Kit from Steam for this ([tts_definitions.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/config/definitions/tts_definitions.py)). If LipGenerator is unavailable, Mantella falls back to `FaceFXWrapper.exe`, requiring `FonixData.cdf` beside it, and passes game type, `USEnglish`, source and resampled WAV paths, output `.lip` path, and text — matching FaceFXWrapper's documented CLI ([ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)) ([FaceFXWrapper README](https://github.com/Nukem9/FaceFXWrapper)).

**Step 4 — Execute headlessly, cross-platform-ish.** On Windows, Mantella writes and runs a hidden `.bat` so no console window appears; on other platforms it writes a shell script that invokes the same Windows binary **through Wine** ([ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)). This is the important nuance for question 4: Mantella's "runs on Linux" story for lip generation is "runs the Windows tool under Wine," not a native port.

**Step 5 — Swap fixed assets in-place.** Mantella does not create new dialogue records at runtime; it overwrites two fixed dialogue assets (`MantellaDi_MantellaDialogu_00001D8B_1` and `…_0018B644_1`) in the target character's voice folder, copying the fresh `.wav` and `.lip` over the previous pair ([skyrim.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/games/skyrim.py)). At install time it seeds every character voice folder with placeholder `MantellaVoice00` assets, so a valid WAV/LIP pair always exists even before the first generated line ([gameable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/games/gameable.py)) ([Mantella-Spell repository](https://github.com/art-from-the-machine/Mantella-Spell)).

**Failure behavior.** The `.lip` copy is wrapped in a nonfatal exception handler, so playback proceeds with the previous/placeholder lip data if generation or copying fails — a deliberate degrade-don't-crash design ([skyrim.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/games/skyrim.py)).

The design lessons for Chronicle are direct: (a) fixed-asset swapping decouples runtime audio from Creation Kit dialogue records; (b) placeholder WAV/LIP pairs guarantee the engine always has something valid to load; (c) lip generation failure is nonfatal; and (d) `Lazy` mode is Mantella's own admission that the generation step is the latency item worth shaving — its official real-time guide quantifies the saving at about 0.5 seconds ([Mantella real-time NPCs guide](https://art-from-the-machine.github.io/Mantella/pages/real_time_npcs.html)).

## 6. Programmatic `.lip` generation: tools, constraints, platforms

Question 3 (can open tooling generate `.lip` headlessly from audio + text, fast enough for runtime?) and question 4 (can it run outside Windows / without the CK?) are answered by comparing the four available generators:

| Tool | What it is | Needs CK? | Needs proprietary data? | Platform | Runtime-suitable? |
|---|---|---|---|---|---|
| **Bethesda LipGenerator.exe** | Official generator shipped with the Skyrim SE Creation Kit under `Tools\LipGen\` ([SteamDB CK update, Dec 2023](https://steamdb.info/patchnotes/12865886/)) | Yes — it is part of the CK install; Mantella's UI instructs users to install the CK from Steam ([tts_definitions.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/config/definitions/tts_definitions.py)) | Yes — `FonixData.cdf` travels with it; third-party wrappers exclude both files for licensing reasons ([Lip Generator GUI](https://www.nexusmods.com/skyrimspecialedition/mods/172869)) | Windows; headless via `-Automated` CLI as used by Mantella ([ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)) | Yes — Mantella prefers it precisely as its first-choice generator ([ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)) |
| **Nukem9 FaceFXWrapper** | Open-source CLI that generates native `.lip` "without using or installing the Creation Kit" ([FaceFXWrapper README](https://github.com/Nukem9/FaceFXWrapper)) | **No CK install needed** — but it wraps Creation-Kit-derived code and is "subject to Bethesda's license agreement" ([FaceFXWrapper README](https://github.com/Nukem9/FaceFXWrapper)) | **Yes** — `FonixData.cdf` is not bundled and must come from the GECK/CK or Nexus ([FaceFXWrapper README](https://github.com/Nukem9/FaceFXWrapper)) | Win32-native: the project is a Windows Visual Studio target built on `WinMain` and Windows process/memory APIs ([FFXW32.cpp](https://github.com/Nukem9/FaceFXWrapper/blob/master/FFXW32/FFXW32.cpp)); it works by patching Creation-Kit code in memory, and on non-Windows it runs only via Wine, as Mantella does ([CreationKit32.cpp](https://github.com/Nukem9/FaceFXWrapper/blob/master/FFXW32/CreationKit32.cpp)) | Yes, with caveats — it is the de-facto runtime generator for Mantella/Pantella/xVASynth ([OpenFaceFX compatibility survey](https://openfacefx.com/docs/COMPATIBILITY/)); but its own release script warns the 64-bit CK output "has not been validated for correctness. Use at your own risk" ([release.ps1](https://github.com/Nukem9/FaceFXWrapper/blob/master/release.ps1)) |
| **xVASynth lip_fuz plugin** | Automatic `.lip` (and optional `.fuz`) creation after each xVASynth synthesis, normal or batch mode; "No Creation Kit use is needed" ([lip and .fuz plugin page](https://www.nexusmods.com/skyrimspecialedition/mods/55605)) | No | Indirectly — it requires FaceFXWrapper.exe to be dropped into the plugin folder ([lip and .fuz plugin page](https://www.nexusmods.com/skyrimspecialedition/mods/55605)) | Windows (inherits FaceFXWrapper's constraint) | Designed for offline batch authoring, but proves the generate-alongside-audio pattern; hard limits: `.lip` generation fails for audio shorter than 0.5 s, and Skyrim wants 44100 Hz `pcm_s16le` ([lip and .fuz plugin page](https://www.nexusmods.com/skyrimspecialedition/mods/55605)) |
| **OpenFaceFX** | MIT-licensed, numpy-only, Python ≥3.9 clean-room lip-sync toolkit with a FaceFXWrapper-compatible CLI shim ([OpenFaceFX repository](https://github.com/OpenFaceFX/OpenFaceFX)) | No | **No** — its explicit purpose is `.lip` writing "no Creation Kit, no FonixData.cdf, no Bethesda-derived code, cross-platform" ([OpenFaceFX issue #12](https://github.com/OpenFaceFX/OpenFaceFX/issues/12)) | Cross-platform pure Python; even runs in-browser via Pyodide ([openfacefx.com](https://openfacefx.com/)) | **Not yet decision-grade**: the writer re-serializes four real samples byte-identically and round-trips its own output, but "the game has not yet loaded a written file," the slot→morph map is a hypothesis, and header field `u22` is copied unresolved ([OpenFaceFX compatibility survey](https://openfacefx.com/docs/COMPATIBILITY/)) |

**Bottom line for questions 3–4.** Headless `.lip` generation from audio + exact text absolutely exists and is runtime-proven — that is FaceFXWrapper's entire purpose and Mantella's shipped behavior ([FaceFXWrapper README](https://github.com/Nukem9/FaceFXWrapper)) ([ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)). But every *proven* generator is Windows-bound and needs Bethesda-owned `FonixData.cdf`; the only *portable, license-clean* option (OpenFaceFX) is explicitly experimental until someone runs its calibration procedure in-game and publishes the slot→morph table — the authors provide a 33-file calibration harness and ask for exactly this verification on issue #12 ([OpenFaceFX compatibility survey](https://openfacefx.com/docs/COMPATIBILITY/)). For Chronicle, whose serving target is a Mac mini, this means: the native `.lip` route is available for Windows users today, but a first-class Mac/Linux story currently means either Wine (Mantella's own approach) or betting on OpenFaceFX maturing ([ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)).

One implementation note from the source that matters for quality regardless of tool: FaceFXWrapper's seven-argument mode resamples internally, while the six-argument mode expects a pre-resampled **16 kHz, 16-bit, single-channel** WAV ([FaceFXWrapper README](https://github.com/Nukem9/FaceFXWrapper)) — and xVASynth's plugin independently warns that very short clips (under 0.5 s) simply do not produce `.lip` output ([lip and .fuz plugin page](https://www.nexusmods.com/skyrimspecialedition/mods/55605)). Chronicle should normalize TTS output format and pad or skip ultra-short lines if it adopts this route.

## 7. The procedural alternative: drive facegen directly, skip `.lip` entirely

The second architectural answer to runtime lip sync avoids the file format altogether: stream phonemes (or a coarse speech envelope) into Skyrim's facegen system while the audio plays.

**The API substrate is mature and documented.** Mfg Fix, a widely installed SKSE plugin, exposes Papyrus functions to set phonemes and modifiers on any actor and to reset them ([Mfg Fix, Nexus Mods](https://www.nexusmods.com/skyrimspecialedition/mods/11669)). Its successor Mfg Fix NG adds smooth animated transitions and extended functions — `SetPhoneme`, `SetModifier`, `SetExpression`, `ApplyExpressionPresetSmooth`, `ResetMFG`, `ResetPhonemes`, `ResetModifiers`, plus dialogue-state helpers like `GetPlayerSpeechTarget` and `IsInDialogue` — with the 16 Skyrim phoneme targets (Aah, BigAah, BMP, ChJSh, DST, Eee, Eh, FV, I, K, N, Oh, OohQ, R, Th, W) enumerated directly in its script source ([MfgConsoleFuncExt.psc](https://github.com/KrisV-777/Mfg-Fix-NG/blob/main/dist/source/scripts/MfgConsoleFuncExt.psc)) ([MfgConsoleFunc.psc](https://github.com/KrisV-777/Mfg-Fix-NG/blob/main/dist/source/scripts/MfgConsoleFunc.psc)). The Nexus release is tested across game versions 1.5.97, 1.6.640, and 1.6.1170, covering the SE/AE install bases Chronicle targets ([Mfg Fix NG, Nexus Mods](https://www.nexusmods.com/skyrimspecialedition/mods/133568)).

**There is complete source-available prior art.** The 2023 Inworld Skyrim mod streamed audio chunks together with per-chunk phoneme metadata from Inworld's API — the client explicitly requests `audio: true, phonemes: true` and processes `additionalPhonemeInfo` — and its SKSE plugin mapped each incoming phoneme to an index and drove `SetExpressionPhoneme` on the speaking actor, clearing all sixteen phoneme slots when the line ended ([Inworld-Skyrim-Mod repository](https://github.com/BlocTheWorker/Inworld-Skyrim-Mod)). This is a working, readable reference implementation of exactly the architecture Chronicle would need, including the random-phoneme fallback generator for speech segments lacking metadata ([Inworld-Skyrim-Mod repository](https://github.com/BlocTheWorker/Inworld-Skyrim-Mod)).

**The current production benchmark is SkyrimNet.** Its release notes describe a dedicated "Lipsync Overhaul": mouth shapes aligned more closely to spoken sounds, mouths returning to neutral between lines, interrupted lines eased back to neutral, better timing on longer lines, and suppression of facial animation for telepathy/thought content — all built on Mfg Fix NG ([SkyrimNet-GamePlugin discussion #423](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/423)) ([SkyrimNet-GamePlugin discussion #387](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/387)). Its public Papyrus shows the coordination pattern: the game-side script blocks until TTS audio is ready before starting subtitles and lip sync together, keeping the two presentation channels aligned ([skynet_Library.psc](https://github.com/MinLL/SkyrimNet-GamePlugin/blob/main/Source/Scripts/skynet_Library.psc)). The native implementation itself is closed, so Chronicle cannot lift the algorithm, but the behavioral contract (start synchronized, ease to neutral, handle interruption, suppress non-speech) is fully documented in the release notes ([SkyrimNet-GamePlugin discussion #423](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/423)).

**Trade-offs versus native `.lip`.** The procedural route eliminates the generation latency, the Windows/proprietary dependency, and the fixed-asset swapping dance — at the cost of writing and tuning a SKSE-side scheduler and accepting coarser mouth shapes than FaceFX-aligned curves. Where Chronicle gets phonemes is flexible: some TTS stacks emit them (Inworld did), and OpenFaceFX's `StreamingGenerator` is explicitly designed to turn chunked phoneme segments into animation frames with a configurable look-ahead latency dial, in bounded memory, cross-platform ([OpenFaceFX streaming documentation](https://github.com/OpenFaceFX/OpenFaceFX/blob/main/docs/api/streaming.md)).

## 8. Is "audio only, frozen mouth" acceptable in practice?

This is the question that decides whether v1 can ship without any lip solution. The evidence splits sharply by presentation context.

**The accepted fallback is placeholder motion, not frozen motion.** Fuz Ro D-oh — one of the most-installed dialogue utilities in Skyrim modding — works by "coercing the engine … into playing a generic silent voice and lip synch file whenever it comes across a dialog response without voice assets of its own," holding subtitles up for a duration computed from word count ([Fuz Ro D-oh, Skyrim Special Edition Nexus](https://www.nexusmods.com/skyrimspecialedition/mods/15109)). Two things follow: even for *unvoiced* dialogue, the established community solution supplies a mouth-movement file rather than leaving faces static; and the fallback that players have accepted for over a decade is *generic* motion, not *no* motion ([Fuz Ro D-oh, original Skyrim Nexus](https://www.nexusmods.com/skyrim/mods/14884)).

**Frozen mouths on audible speech are treated as defects.** When NPC mouths stop moving during speech, players open troubleshooting threads and hunt down the offending mod rather than accepting the presentation ([Nexus Forums: NPC mouths not moving while talking](https://forums.nexusmods.com/topic/7283886-npc-mouths-not-moving-while-talking/)). The community reverse-engineered and patched an engine-level lip-sync desync bug rather than live with it, and maintainers of engine-fix mods receive bug reports — with videos — when lip animation fails to trigger at all ([AFK Mods: Lip Sync Bug — Finally Fixed](https://www.afkmods.com/index.php?/topic/4473-skyrim-lip-sync-bug-finally-fixed/)) ([Engine Fixes issue #7](https://github.com/aers/EngineFixesSkyrim64/issues/7)).

**The shipped AI-NPC mods vote with their architecture.** Mantella's own real-time tuning guide tells users to switch lip generation to `Lazy` — sacrificing sync on only the first sentence — rather than to `Disabled`, even when optimizing for response time ([Mantella real-time NPCs guide](https://art-from-the-machine.github.io/Mantella/pages/real_time_npcs.html)). Mantella also seeds placeholder WAV/LIP pairs into every voice folder so the engine always has lip data of some kind, and its failure path degrades to stale-but-valid lip data rather than to nothing ([gameable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/games/gameable.py)) ([skyrim.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/games/skyrim.py)). SkyrimNet invested in a named lipsync overhaul rather than shipping frozen faces ([SkyrimNet-GamePlugin discussion #423](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/423)).

**Verdict for question 5.** In first-person dialogue with the NPC facing the player — Chronicle's exact scenario — audible speech with a completely frozen mouth is the worst-tested and most bug-coded presentation available. "Audio with generic/placeholder mouth motion" has a decade of accepted precedent; "audio with frozen mouth" does not ([Fuz Ro D-oh](https://www.nexusmods.com/skyrimspecialedition/mods/15109)) ([Nexus Forums thread](https://forums.nexusmods.com/topic/7283886-npc-mouths-not-moving-while-talking/)).

## 9. Latency: what runtime lip data actually costs

Two evidence classes must not be conflated.

| Measurement | Value | Evidence class |
|---|---|---|
| Mantella `Lazy` lip mode saving | **≈0.5 s** off response time when skipping per-line lip generation (first sentence only) | Shipped-system, vendor-published practical figure; covers the real LipGenerator/FaceFXWrapper subprocess path ([Mantella real-time NPCs guide](https://art-from-the-machine.github.io/Mantella/pages/real_time_npcs.html)) |
| OpenFaceFX naive `.lip` generation, 0.6 s WAV | **2.4 ms** median (output 2,859 bytes) | First-party micro-benchmark from this research session: silent 16 kHz mono WAVs through OpenFaceFX's FaceFXWrapper-compatible shim on a Linux sandbox; output not verified in-game — lower bound only |
| OpenFaceFX naive `.lip` generation, 1.5 s WAV | **3.2 ms** median (5,694 bytes) | Same caveat |
| OpenFaceFX naive `.lip` generation, 3.0 s WAV | **4.2 ms** median (10,419 bytes) | Same caveat |
| OpenFaceFX naive `.lip` generation, 6.0 s WAV | **6.3 ms** median (19,869 bytes) | Same caveat |
| xVASynth plugin minimum clip | `.lip` generation **fails below 0.5 s** of audio | Vendor-documented constraint, relevant to short barks ([lip and .fuz plugin page](https://www.nexusmods.com/skyrimspecialedition/mods/55605)) |

Three conclusions follow. First, the proven Windows-native path costs on the order of half a second per line in a real shipped pipeline — noticeable but manageable, and Mantella's `Lazy` mode shows the accepted mitigation: skip it on the first sentence so the reply starts sooner, then sync subsequent sentences ([Mantella real-time NPCs guide](https://art-from-the-machine.github.io/Mantella/pages/real_time_npcs.html)). Second, the file-writing step itself is not inherently slow — naive pure-Python generation is millisecond-scale in our benchmark — so a verified clean-room writer could plausibly make native `.lip` generation effectively free; the caveat is that OpenFaceFX's output has never been loaded by the game, and its FaceFXWrapper-compatible path uses naive text-to-duration timing rather than acoustic alignment ([OpenFaceFX compatibility survey](https://openfacefx.com/docs/COMPATIBILITY/)) ([OpenFaceFX repository](https://github.com/OpenFaceFX/OpenFaceFX)). Third, the procedural route has no generation step at all — its cost is a per-frame scheduling budget inside SKSE, which is why SkyrimNet's documented work items are about animation *quality* (twitchiness, neutral resets, interruption easing) rather than latency ([SkyrimNet-GamePlugin discussion #423](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/423)).

## 10. Decision for Chronicle

**Does Chronicle need to solve lip sync before shipping spoken dialogue?** It needs to solve *mouth presentation*; it does not need to solve *lip-sync generation*, because both are already solved by shippable prior art. The corrected decision framing:

| Decision | Answer | Basis |
|---|---|---|
| Ship voice-only with **frozen mouth** as the intended v1 default? | **No** — not for close-up first-person dialogue | Frozen mouths on audible lines are bug-coded by players; even unvoiced-dialogue tooling ships generic lip motion instead ([Nexus Forums thread](https://forums.nexusmods.com/topic/7283886-npc-mouths-not-moving-while-talking/)) ([Fuz Ro D-oh](https://www.nexusmods.com/skyrimspecialedition/mods/15109)) |
| Ship with **some** mouth movement even if coarser than FaceFX quality? | **Yes** — this is the honest v1 | Placeholder/generic motion has decade-long accepted precedent; SkyrimNet ships procedural animation in production ([Fuz Ro D-oh](https://www.nexusmods.com/skyrimspecialedition/mods/15109)) ([SkyrimNet-GamePlugin discussion #423](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/423)) |
| Build **native `.lip` generation** into v1? | Only as the Windows compatibility path | Proven by Mantella but Windows-bound, `FonixData.cdf`-dependent, ≈0.5 s/line, and its 64-bit output is self-described as unvalidated ([FaceFXWrapper release.ps1](https://github.com/Nukem9/FaceFXWrapper/blob/master/release.ps1)) ([Mantella real-time NPCs guide](https://art-from-the-machine.github.io/Mantella/pages/real_time_npcs.html)) |
| Wait for **OpenFaceFX** before shipping? | No — adopt when verified | Byte-valid writer exists, but in-game loading and slot→morph mapping are open verification tasks the authors flag as unresolved ([OpenFaceFX compatibility survey](https://openfacefx.com/docs/COMPATIBILITY/)) |

### Recommended v1 architecture

1. **Default: procedural mouth animation over Mfg Fix NG.** Chronicle's SKSE component (which it needs anyway for game-state integration) drives the speaking actor's face while the TTS WAV plays: apply phoneme targets with smooth transitions, ease to neutral at line end and on interruption, and suppress animation for non-spoken content — the exact behavioral contract SkyrimNet documents for its overhaul ([SkyrimNet-GamePlugin discussion #423](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/423)). The control API is documented Papyrus with the 16 phoneme slots enumerated in source ([MfgConsoleFuncExt.psc](https://github.com/KrisV-777/Mfg-Fix-NG/blob/main/dist/source/scripts/MfgConsoleFuncExt.psc)). For drive data: use phoneme timings if the TTS stack emits them (Inworld's mod shows this working end-to-end), else generate them from text+audio with OpenFaceFX's streaming phoneme layer, else fall back to a conservative syllable-rate envelope as Inworld's random-phoneme fallback did ([Inworld-Skyrim-Mod repository](https://github.com/BlocTheWorker/Inworld-Skyrim-Mod)) ([OpenFaceFX streaming documentation](https://github.com/OpenFaceFX/OpenFaceFX/blob/main/docs/api/streaming.md)).
2. **Synchronize channels like SkyrimNet does:** block the start of subtitles and mouth animation until the audio is actually ready to play, so the three channels never drift ([skynet_Library.psc](https://github.com/MinLL/SkyrimNet-GamePlugin/blob/main/Source/Scripts/skynet_Library.psc)).
3. **Compatibility path: Mantella-style native `.lip` on Windows.** Reuse the fixed-asset-swap pattern with placeholder WAV/LIP seeds and nonfatal failure handling ([skyrim.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/games/skyrim.py)) ([gameable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/games/gameable.py)). Try `LipGenerator.exe` then FaceFXWrapper, and consider a `Lazy` equivalent for first lines — every element of this pattern is visible in Mantella's audited source ([ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)). Normalize TTS output to 44100 Hz 16-bit PCM and handle sub-0.5 s lines specially, per the xVASynth plugin's documented constraints ([lip and .fuz plugin page](https://www.nexusmods.com/skyrimspecialedition/mods/55605)).
4. **Research track: verify OpenFaceFX in-game.** Run its `lip-calibrate` harness (33 single-slot `.lip` files) against known vanilla lines, publish the slot→morph table to issue #12 as the authors request, and re-evaluate it as Chronicle's cross-platform native `.lip` generator once verified ([OpenFaceFX compatibility survey](https://openfacefx.com/docs/COMPATIBILITY/)). Our benchmark indicates the generation cost would be negligible if verification succeeds (§9).
5. **Frozen mouth is a debug/failure mode only.** Acceptable for development builds, off-screen/virtual speakers, narration, and an explicit subtitles-only accessibility mode; it should never be the default for an NPC the player is looking at, per the acceptability evidence in §8 ([Nexus Forums thread](https://forums.nexusmods.com/topic/7283886-npc-mouths-not-moving-while-talking/)) ([Fuz Ro D-oh](https://www.nexusmods.com/skyrimspecialedition/mods/15109)).

### Pre-ship verification checklist

| # | Check | Pass criterion |
|---|---|---|
| 1 | Mouth animation starts synchronized with audio onset for lines of 1–8 s | No perceived lead/lag in first-person dialogue; the engine's built-in FaceFX delay behavior is not fighting the procedural drive ([AFK Mods lip-sync bug analysis](https://www.afkmods.com/index.php?/topic/4473-skyrim-lip-sync-bug-finally-fixed/)) |
| 2 | Interruption handling: player exits dialogue mid-line | Mouth eases to neutral rather than freezing mid-phoneme — the behavior SkyrimNet's overhaul explicitly implements ([SkyrimNet-GamePlugin discussion #423](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/423)) |
| 3 | Non-speech outputs (thoughts, telepathy, narration) | No facial animation, matching SkyrimNet's documented suppression ([SkyrimNet-GamePlugin discussion #387](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/387)) |
| 4 | Sub-0.5 s barks | Defined behavior (skip lip generation or clamp) — the xVASynth plugin's documented failure floor ([lip and .fuz plugin page](https://www.nexusmods.com/skyrimspecialedition/mods/55605)) |
| 5 | Actor-crowded scenes | Mouth animation still triggers; Skyrim has a known engine issue where facial animation stops with many actors loaded ([Engine Fixes issue #7](https://github.com/aers/EngineFixesSkyrim64/issues/7)) |
| 6 | Game versions 1.5.97 / 1.6.640 / 1.6.1170 | Mfg Fix NG reports testing on all three; validate Chronicle's scheduler on each ([Mfg Fix NG, Nexus Mods](https://www.nexusmods.com/skyrimspecialedition/mods/133568)) |
| 7 | If native `.lip` path is enabled: generated files actually animate in-game | FaceFXWrapper's own release notes state 64-bit CK output "has not been validated for correctness" — Chronicle must validate on its own content ([release.ps1](https://github.com/Nukem9/FaceFXWrapper/blob/master/release.ps1)) |
| 8 | If OpenFaceFX is adopted later: slot→morph calibration completed and confirmed in-game | The authors state this is the one unresolved correctness fact ([OpenFaceFX compatibility survey](https://openfacefx.com/docs/COMPATIBILITY/)) |

## 11. Closing summary

The premise of the perceived blocker — that runtime speech conflicts with Skyrim's pregenerated `.lip` expectation — is real but already routed around by the ecosystem, twice. Mantella proves a mod can synthesize a line, generate a native `.lip` for it in roughly half a second, and swap it onto fixed dialogue assets at runtime, degrading gracefully when generation fails ([ttsable.py](https://github.com/art-from-the-machine/Mantella/blob/main/src/tts/ttsable.py)) ([Mantella real-time NPCs guide](https://art-from-the-machine.github.io/Mantella/pages/real_time_npcs.html)). SkyrimNet proves a mod can skip the file format entirely and drive facegen procedurally at production polish ([SkyrimNet-GamePlugin discussion #423](https://github.com/MinLL/SkyrimNet-GamePlugin/discussions/423)). What the evidence does not support is shipping audible face-to-face dialogue with no mouth movement at all: the community's accepted minimum is generic placeholder motion, and frozen mouths read as malfunction ([Fuz Ro D-oh](https://www.nexusmods.com/skyrimspecialedition/mods/15109)) ([Engine Fixes issue #7](https://github.com/aers/EngineFixesSkyrim64/issues/7)). Chronicle's honest v1 is therefore: **procedural mouth animation now, native `.lip` as a Windows compatibility option, clean-room `.lip` as a verified upgrade later, and frozen mouths never on purpose.**
